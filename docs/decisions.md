# Архитектурные решения

Этот файл содержит журнал значимых решений. Новые записи добавляются в конец и
не переписывают историю: изменённое решение получает новую запись со ссылкой на
предыдущее.

## ADR-001: Модульный монолит

- Статус: принято
- Дата: 2026-07-27

### Решение

Backend создаётся как один Spring Boot deployment с внутренними доменными
модулями.

### Причина

На старте важнее простые транзакции, тестирование и эксплуатация. Микросервисы
увеличат сложность без подтверждённой пользы.

## ADR-002: Java и Spring Boot для backend

- Статус: принято
- Дата: 2026-07-27

### Решение

Использовать Java 21, Spring Boot, Spring Security, JPA, Liquibase и
Testcontainers.

### Причина

Это знакомый владельцу проекта стек с развитой экосистемой для API, безопасности
и работы с PostgreSQL.

## ADR-003: React PWA раньше нативного клиента

- Статус: принято
- Дата: 2026-07-27

### Решение

Первым клиентом становится адаптивное React-приложение с возможностью установки
как PWA. SwiftUI-клиент рассматривается после проверки продукта.

### Причина

Один веб-клиент быстрее покрывает desktop и мобильные сценарии. Ограничения PWA
будут оцениваться на реальном использовании.

## ADR-004: PostgreSQL является источником данных

- Статус: принято
- Дата: 2026-07-27

### Решение

Основные данные хранятся в PostgreSQL. YAML сохраняется как формат импорта и
экспорта.

### Причина

Синхронизация, связи между пользователями и календарями, транзакции и поиск
требуют серверного хранилища.

## ADR-005: Один VPS и Docker Compose для первого production

- Статус: принято
- Дата: 2026-07-27

### Решение

Первая production-версия размещается на одном VPS под управлением Docker
Compose и Caddy.

### Причина

Это достаточно просто и экономично для начальной нагрузки. Резервные копии
обязательно хранятся вне VPS.

## ADR-006: Production-деплой только через GitHub Actions

- Статус: принято
- Дата: 2026-07-27

### Решение

Образы публикуются в GHCR с тегом Git commit SHA. Production Environment требует
ручного подтверждения. Разработчики и агенты не выполняют прямой production
deploy.

### Причина

Проверки, журнал операций и разделение ответственности снижают риск случайного
повреждения production.

## ADR-007: Стандартизированная работа со временем

- Статус: принято
- Дата: 2026-07-27

### Решение

Сохранять моменты времени в UTC, IANA time zone отдельно, события на весь день
как даты и использовать RRULE-совместимый формат повторений.

### Причина

Это предотвращает типичные ошибки при смене часовых поясов и переходах на
летнее время и упрощает интеграцию с календарными форматами.

## ADR-008: Node.js 24 для frontend

- Статус: принято
- Дата: 2026-07-27

### Решение

Использовать Node.js 24 или новее для установки зависимостей, тестирования и
сборки frontend.

### Причина

Установленный ранее Node.js 18.12 не удовлетворяет требованиям современных
инструментов lint и тестирования и вынуждает использовать версии с известными
уязвимостями.
